# 公式メディアの記事制作統合

2026-09-22開始。画面は `https://seo.layr.co.jp/articles/`。

## 操作とデータ

- 概況、キーワード、承認、記事一覧、計測、根拠資料、設定を同じ画面で切り替える。
- 既存の公開記事のアクセス実績・改善メモは「公開記事の改善」で維持する。
- 記事ツールの既存データベースと処理を共有する。キーワードや原稿の複製移行はしない。
- 記事制作エンジン・秘密情報・夜間ジョブは既存の非公開 `layr-kiji` Workerに残す。
- サジェスト指標は検索ボリュームではない。既存CSVの条件不明な数値は参考値として区別する。
- 新CSV取込は整数と範囲を区別して原文を保存する。範囲の代表値を作らない。不正な数値を含むファイルは書込前に止める。
- 計測の未取得は「—」。取得元ごとの最終データ日を確認する。

## 接続

ブラウザ → 既存Cloudflare Access → `/api/seo/kiji/*` → サービスバインディング `KIJI_WORKSPACE` → `layr-kiji` の `SeoWorkspaceApi`。

中継先は固定し、操作先・メソッド・JSON項目・容量を制限する。ブラウザのCookie、Accessトークン、任意ヘッダーは中継しない。記事制作用の秘密情報や非公開エンジンをこのリポジトリに置かない。

## 公開手順

原稿確認 → 公開用の変更を作成 → GitHubのPRで変更とCIを確認 → 承認・マージ → デプロイ → 画面の公開確認。

公開先は `layrinc/layr-hp` の `src/content/blog` と `public/blog-img`。PR作成だけでは「公開済み」にしない。旧リポジトリへの既知の旧設定は、記事ツール側の解決処理で現行の公開先へ向ける。設定データを一括上書きしない。

「公開先への接続を確認」は読み取り接続の検証。実際の書込権限を保証するものではない。GitHubトークンには対象リポジトリへの Contents / Pull requests の適切な権限が必要。

## 重複操作

旧画面、新画面、夜間ジョブで書込排他を共有する。通信断時に同じ記事を自動再公開しない。公開結果が不明な場合は変更・履歴を確認してから復旧する。長時間処理中が続く場合の確認・条件付き解除手順は非公開の記事ツールの運用資料を参照する。

## 配備順

1. 記事ツール側のテストと変更レビューを完了し、既存Workerへnamed entrypointを追加する。
2. このリポジトリのPRでUI・サービス接続・回帰テストを検証する。
3. PRをマージし、既存Cloudflareの公開完了を確認する。
4. 認証済みの画面から読取のみで、既存キーワード・記事・設定が一致することを確認する。

検証で実記事を生成・公開したり、運転モードを変更したりしない。新規データベース・新規cron・DNS変更は不要。

## ローカル検証

`node --test tests/kiji-*.test.mjs`、通常のサイトビルド・回帰テスト・デザインゲート・Worker dry-runを行う。ブラウザの操作検証は本番とは接続しない架空データで実施する。
