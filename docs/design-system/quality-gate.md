## 0. この文書の適用範囲

- **これから新規に作るものの基準**。既存サイトの一斉是正はまだ承認されていない。
- 既存ファイルを触る時は、触った箇所だけ基準に合わせる。ページ全体の作り直しは承認を取ってから。
- 優先順位: **河出さんの明示指示 > プロジェクトの既存トークン > この閾値表**。
- 閾値を変える時は `scripts/design-gate.sh` と本ファイルの両方をそろえる。片方だけ直さない。

## 2. 目視ゲート

全部YESで通す。1つでもNOなら提出しない。

### 2-1 トークン忠実性

- [ ] このプロジェクトのトークン正本ファイルを開いてから書いたか
- [ ] 正本に無い色・書体・角丸・影を1つも新規追加していないか
- [ ] グラデはLAYR指定の `#0499AF → #77D55C`（横）1本だけか。用途は4つ（ラベル帯／円形フローの環／番号バッジ／三角矢印）に収まっているか。表紙相当だけ淡緑 `#C1E392 → #B6DD75`
- [ ] サブ色を役割どおりに使ったか（黄 `#F6CC01`＝強調バッジ／橙 `#E9A32F`＝推奨リボン／赤 `#FF5757`＝最重要数値・ステップ番号／淡水色 `#D6EEF1`＝面・チップ）。役割外に転用していないか
- [ ] 派生色を新しい変数として増やしていないか（その場の `color-mix` / `oklch` で済ませたか）
- [ ] `:root` を2回宣言してトークンを殺していないか
- [ ] CSSを末尾追記で積層していないか（既存定義を書き換えたか。「vNN追加レイヤー」を積まない）
- [ ] 二重管理を両方そろえたか

二重管理の実在箇所（`株式会社LAYR/layr-hp/` 配下）:

| 正本 | 同時に直す先 |
|---|---|
| `src/styles/style.css` の `:root` | `src/data/theme.json` / `public/admin/cms/preview.css` |
| ISO図解の色 | `src/lib/iso/*.mjs` の直値 |
| サービス数・capBox数 | `src/pages/service/index.astro` のMETA配列 と `src/data/pages/service.json` |
| よろず屋のトンマナ | `public/yorozuya/index.html`（ビルド系統外。共通レイアウトを通らない） |

### 2-2 モード忠実性

- [ ] 1プロジェクト1モードを守ったか。ページ内で切り替えていないか
- [ ] 標準はA。BとCは河出さんの明示指示がある時だけ発動したか
- [ ] BとCのトークンをページscoped変数（`--edit-*` / `--wa-*`）で持ち、グローバル `:root` を上書きしていないか
- [ ] hoverの向き（A=動かない / B=沈む / C=浮く / D=背景の微変化）がモード定義と一致しているか
- [ ] 強調手段がモード定義の1種類だけか（A=文字色替え / B=淡黄マーカー62% / C=朱文字色替え / D=強調なし）
- [ ] マーカーの塗り開始位置がモードの1値に固定されているか（58/62/66/68/70%の混在を作らない）
- [ ] 社内ツールの teal 使用可否を「LAYRとして名乗るものか」で判定したか。ツール固有色を新規に作っていないか

### 2-3 平凡さの排除

- [ ] design plan に `signature:` を1行で書けたか。書けないなら着手しない
- [ ] 等分3カラムの連打を1ページに1回は崩したか（崩しは1ページ2〜3箇所まで）
- [ ] 「1文しか置かないセクション」または明確な余白の谷を作ったか
- [ ] 見出しの強調は1語だけか。文全体を色にしていないか
- [ ] 絵文字を見出しアイコンに使っていないか
- [ ] 頼まれていないセクション（私たちの価値観／選ばれる理由／チーム紹介）を埋め草に足していないか
- [ ] `Inter` `Roboto` `Arial` `Space Grotesk` を「選択」として使っていないか（Dモードのsystem fontは意図的な選択なのでOK）
- [ ] 紫→青グラデ・サンセットグラデ・浮遊グラデオーブを使っていないか（**LAYR指定のティール→ライトグリーンは正規の意匠。混同しない**）
- [ ] 16px以上の大角丸を全面適用していないか
- [ ] マーキー帯・巨大英字ウォーターマーク・斜めカットを作っていないか（v8で作りv9で削除済み。もう作らない）
- [ ] ダミー統計・偽ロゴ・偽の顔を置いていないか。素材が無い時はラベル付きプレースホルダ（`[hero: 実UIスクショ 1400×900]`）にしたか

- [ ] このページは「どのAIでも出せるもの」になっていないか

### 2-4 構造・計測

- [ ] `<h1>` がちょうど1つあるか
- [ ] スクロール表示が既存の1機構に乗っているか（新しい流派を作っていないか）
- [ ] CVボタンに `gtag('generate_lead')` が入っているか（LPのみ）
- [ ] FAQは `details/summary` 型で書いたか（JSON-LD自動生成がこれに依存する）
- [ ] 無効化して残したデッドコード（`display:none` / `content:none` で殺したCSS）を作っていないか。消す時は消す
- [ ] CSSで殺した機能をJSONに残していないか（効かないスイッチを作らない）
- [ ] ビルド系統の外にHTMLを置いていないか

### 2-5 不可侵

「◯◯風にして」で変えてよいのは、**色・装飾・紋様・カード造形・影・枠・余白・モチーフ・レイアウトだけ**。

- [ ] 書体を変えていないか（筆文字・明朝・デコラティブへの無断置換）
- [ ] 文言・言い回しを変えていないか（和風の言い換えリライト）
- [ ] 数字の表記を変えていないか（算用数字→漢数字）
- [ ] セクション名・Q&A・アイコンの表記を変えていないか
- [ ] 書体を寄せたい時、実施前に「読みやすさ優先で現状のままにしますか？」と聞いたか
- [ ] 対外物にMEOを掲げていないか／広告運用の金額を書いていないか
- [ ] サービス名の呼称を1表記に統一したか
- [ ] 1440 / 768 / 375 の3幅で横スクロールが出ないか
- [ ] 本文コントラスト4.5:1以上・大見出し3:1以上か

理由: LPの読み手は地方の社長。**可読性が最優先**。

## 3. ゲートに落ちた時

1. **新規制作物**: 必ず直してから提出する。閾値を緩めない。
2. **既存資産を触った時**: 触った箇所だけ基準に合わせる。ページ全体の是正は承認案件。
3. **手動スキップが2回連続で発生した**: 閾値が現実に合っていない。閾値側を直し、本ファイルと `scripts/design-gate.sh` を同時に更新する。
4. **河出さんが「これ違う」と差し戻した**: その場で `references/antipatterns.md` のC節に実例つきで1行追記する。記憶頼みにしない。
