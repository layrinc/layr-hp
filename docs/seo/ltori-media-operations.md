# エルトリ採用ノートの運用

公開先: https://layr.co.jp/service/ltori/media/

記事から採用LINEの相談・サービス資料へ案内する。対象は採用担当者。運営・記事の最終確認は株式会社LAYRが行う。

## 記事を追加する

1. `src/content/recruitment/` に英数字とハイフンのファイル名でMarkdownを作成する。ファイル名は公開URLになるため、公開後は原則変更しない。
2. 次のフロントマターを記入し、本文を執筆する。

```yaml
---
title: 採用担当者の疑問に具体的に答えるタイトル
description: 記事で分かることを簡潔に記載
date: 2026-09-20
category: 採用導線
target_keyword: 調査した検索キーワード
draft: true
---
```

カテゴリーは `採用導線`・`応募後フォロー`・`外注・比較` のいずれか。H1は自動生成されるので、本文はH2から始める。料金・仕様はサービスの正本データを確認し、架空の実績や検索順位保証は書かない。出典は本文にリンクする。地域記事は対象地域の実際の情報を確認できる場合のみ作成し、地名だけを入れ替えた記事は増やさない。

3. 社内で内容・出典・表現を確認し、公開日と `draft: false` を設定する。
4. 作業ブランチで `npm run build`、`node --test tests/*.test.mjs`、`bash scripts/gate-regression.sh` を実行。PRのCloudflareプレビューでPCとスマホを確認する。
5. 承認後にPRをマージし、本番の記事・相談導線・サイトマップを確認する。

`draft: true` と未来日付の記事は記事ページ・一覧・サイトマップに出ない。日付の判定はビルド時のため、予約日時が過ぎても再ビルドなしでは公開されない。自動予約投稿は未導入。

## 公開後の確認と改善

週1回を目安に、Search Consoleで表示回数・クリック数・検索語を確認する。GA4では `ltori_media_cta_click` の記事・配置別のクリックを確認する。相談CTAのクリックと相談完了は別の指標として扱い、クリックをリード数に数えない。GA4/Search Consoleの集計には、それぞれのプロパティへのアクセスと実際のデータ到着の確認が必要。

月1回、読まれた記事と相談につながったテーマを見直し、古い記述・リンク切れ・分かりにくい箇所を更新する。実質的な更新をした場合は本文末尾に更新日と変更点を記載する。候補テーマは面接前リマインド、応募者への初回連絡、採用LINEの委託範囲など。検索需要と既存記事の重複を調べてから着手する。

## 問い合わせの受け付け

サービス導入の相談は既存の `/contact/?service=ltori` に接続する。記事の質問・訂正・取材はメディア専用の `/service/ltori/media/contact/` で受け付ける。受信先は `src/data/settings.json` の会社メール（現在 info@layr.co.jp）。FormSubmitの既存仕組みを使用し、メディア問い合わせの件名を分ける。

専用フォームは必須入力・同意確認、送信中と送信後の重複防止、12秒のタイムアウト、失敗時の入力保持を実装する。受付サービスの成功応答とメール受信は別の確認事項。公開前の実送信では、受信先の有効化、メール到着、Reply-To、迷惑メール振り分けまで確認する。今回の検証は通信の模擬テストまでで、実送信は未実施。編集部問い合わせは営業リードに加算せず、個人情報も計測へ渡さない。

## 障害・取り下げ

記事だけ取り下げる場合は `draft: true` に変更してPR経由で再公開する。URLが404になるため、恒久的な移転は転送も検討する。リリース全体の障害は該当PRのrevertを別PRで作成し、CI・プレビュー確認後にマージする。mainへの直接pushやDNS変更は行わない。

## 2026-09-21 追加: 記事からの問い合わせを確認する

ヘッダー・末尾CTAと本文中の採用相談／エルトリ資料リンクは、`source=media/記事ID` を引き継ぐ。一覧は `source=media`。本文リンクの引き継ぎはJavaScriptで行う。フォームの許可リストは公開記事からビルド時に生成され、下書き・未来記事・未知のIDは受理しない。

| イベント | 意味 | 備考 |
|---|---|---|
| `ltori_media_cta_click` | 記事から相談・資料へのクリック | リードに加算しない。`cta` でヘッダー・本文・末尾を区別 |
| `ltori_media_inquiry_complete` | メディアからの相談フォーム受付成功 | `page_source` が記事ID。メール受信の保証とは別 |
| `ltori_media_document_complete` | メディアからの資料請求受付成功 | 相談とは別集計 |
| `generate_lead` | サイト共通のフォーム受付成功 | 上2イベントと同じ申込なので合算しない。`method` で相談と資料を区別 |

`page_source` は受信メールの「ご覧になったページ」にも記事名として残る。氏名・メール・問い合わせ本文はGA4イベントに含めない。資料請求は受付応答の成功を確認してから計上する。サンクスページの直接表示や再読込は追加リードに数えない。

GA4は現在のLAYRプロパティを利用する。標準レポートで記事別の `page_source` を集計するには、必要に応じてイベントスコープのカスタムディメンションを登録する。現時点で専用管理画面のGoogle取得は地域LP向けであり、記事の自動集計には対応していない。クリック・申込・GSCデータを未取得のまま0にしない。

GA4への遷移前イベント通知は公式の [event_callback / event_timeout](https://developers.google.com/tag-platform/gtagjs/reference/parameters) を使い、タグが遮断されても1秒後には資料ページへ進む。

## 2026-09-21 追加: エルトリ採用ノートのメディア構成

メディア名は河出さん選定の「エルトリ採用ノート」。サービス名は「エルトリ」のまま。KUZENブログを参考に、記事カード2列＋右サイドバー、スマホでは1列の一覧に変更した。記事URLと本文は維持する。

| 導線 | URL |
|---|---|
| 記事一覧 | `/service/ltori/media/` |
| このメディアについて・運営会社 | `/service/ltori/media/about/` |
| 採用導線 | `/service/ltori/media/category/recruitment-flow/` |
| 応募後フォロー | `/service/ltori/media/category/follow-up/` |
| 外注・比較 | `/service/ltori/media/category/outsourcing/` |

ヘッダーのカテゴリー名を押すと、該当カテゴリーの記事だけを掲載したページへ移動する。新しい記事は既存のカテゴリーを指定すれば、一覧・カテゴリー別ページ・件数・サイトマップにビルド時に反映される。カテゴリー自体を追加するときは、コンテンツスキーマと `src/lib/ltori-media.mjs` の定義を揃える。

一覧は公開日降順で、JavaScript有効時は18件ずつ「もっと見る」で追加表示する。現在は3記事のためボタンは表示されない。JavaScript無効時は全記事とリンクを表示する。サムネイルは短い見出しと、河出さん指定のISOME LAB公式イラストを組み合わせる。公式の色変更機能で緑に調整し、SVGを自サイトから配信する。画像対応は `src/lib/ltori-media.mjs` の `mediaArtwork`、短い見出しは `articleVisuals` に集約。正式な記事タイトルはカード本文に全文表示する。出典は公開画面に表示せず、内部台帳 `docs/design-system/20260921-media-assets.md` に記録する。

右側の「最初に読みたい記事」はカテゴリーごとの編集選定であり、アクセスランキングではない。閲覧データの取得なしに「人気記事」やPV数を表示しない。

メディア専用ヘッダー・フッターを使用する。最新の添付指定に合わせ、記事末尾に編集部紹介、テーマ別のサービス案内、おすすめ記事、画像付き関連記事を配置した。サービス案内のクリックは `article_service` / `article_consultation` として区別する。記事本文と相談リンクには `source=media/記事ID` を引き継ぐ。記事以外の一覧・カテゴリー・Aboutは `source=media` を使用し、カテゴリースラッグを記事IDとして送らない。

フッターは「このメディアについて」「運営会社」「お問い合わせ」「プライバシーポリシー」「サービスサイトを見てみる」。フッターのサービスサイトへのクリックは `ltori_media_cta_click` の `service_site` として記録し、申込完了・リードとは別集計する。Aboutにはメディアの目的・編集方針・運営元とサービスの関係を明記する。

実装・検証はローカルプレビューまで。本番反映はリポジトリのPR・承認手順に従う。確認記録は `docs/qa/ltori-media-hub-20260921.md`。
