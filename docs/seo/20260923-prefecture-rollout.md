# 全国市SEO・47都道府県の公開予定

2026-09-23の確定指示：北海道から沖縄まで、1日1都道府県ずつ、その県の全市を対象にする。対象マスターは792市。町・村・特別区・行政区は今回の自動公開の対象外で、既存の編集データは保持する。

## 日程と公開

`regional_campaign/config` の `enabled` と `startDate` が正本。既定は無効・開始日未設定。開始日から47日間、都道府県コード順に割り当て、各県内は市のコード順に処理する。9:17 JSTと再確認10:17 JSTでその日の担当県だけを公開する。固定の20件上限は廃止。未確認原稿を数合わせで公開しない。

公開済みの静的3市とD1上の10市は維持する。同じ版の再実行、当日の再配達、同時実行、翌日の県の先取りを防ぐ。確認済みの訂正は既存公開版への更新として扱う。採用ノートの月10本・新規公開間隔3日以上、公式メディアの保留は変更しない。

管理画面に47県の予定日・対象数・公開済み・準備済み・要対応を表示する。47日経過は日程終了であり、未公開があれば網羅完了とは表示しない。日程を過ぎた不足分は自動で翌県へ混ぜず、一覧に残す。

## 地域専用の自動制作

03:17・05:17 JSTのGitHub Actions `prepare` が、当日と翌日の担当県（開始前は北海道）を準備する。1回の受付で1市の1工程、最大240工程/実行・90分。外部への支払いを伴う処理は private Worker `layr-kiji` のサービス専用 `RegionalEditorialApi` に分離し、既存の公式メディアの停止設定・記事DB・公開処理には触れない。

1. 公式資料を実際に検索し、検索結果のURLと引用証拠に裏付けられた市固有の事実を保存。
2. 調査結果に基づき企業の採用担当者向け原稿と根拠対応表を作成。
3. 別のAI呼び出しで調査事実・本文・引用証拠を照合。
4. 構造・数値・類似本文の検査を通過した原稿だけ、`AI出典照合` と明記して公開待ちに追加。

既存の下書き・停止中原稿は上書きしない。出典不足、照合不合格、類似性が高い原稿は要対応へ送る。AI確認は人間の確認を保証するものではない。調査結果の指示文は信頼せず、記事の根拠としてだけ扱う。

`regional_editorial/config.enabled` が制作の別スイッチ。公開の一時停止も尊重し、呼び出し中に停止・開始日変更があれば原稿の最終登録を止める。

## 費用と再実行

private Workerの `REGIONAL_TOTAL_BUDGET_USD`（キャンペーン合計）・`REGIONAL_DAILY_BUDGET_USD`（日本時間1日）を両方設定しなければAIを呼び出さない。各工程の費用を呼び出し前にD1で確保し、判明した使用量で精算する。不明な実行は確保額を保持し、自動で再課金しない。

実行IDはキャンペーン・市コード・工程で固定し、工程入力のハッシュが一致した保存結果を再利用する。別の入力で同じIDを使うこと、未保存の調査結果を後工程に持ち込むことは拒否する。現在の利用モデルと料金の出典はprivate側の運用資料に記録する。

費用上限未設定・接続不明・要確認原稿がある場合、ワークフローは成功扱いで隠さず担当者の確認が必要な状態を返す。有効化前の既定は無効で、コード反映だけでは課金を始めない。

## 検証と反映
