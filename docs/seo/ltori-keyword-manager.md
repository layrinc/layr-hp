# エルトリ 全国SEOキーワード管理

2026-09-18。地域LPを運用するための管理ツールを `/tools/ltori-seo/` に実装する。LPの「ほかの対応地域」と直下の都道府県・全国一覧リンクはユーザー指示により全地域から削除。追加指示に合わせて、冒頭のパンくず行と地域LPのBreadcrumbList構造化データも削除。最下部の相談欄と共通フッターの全国一覧リンクも地域LPでは表示しない。都道府県の子地域一覧、全国索引、サイトマップは維持する。

## Design plan

- 対象: 全国の地域ページ・対策キーワード・検索実績・改善タスクの管理。
- モード: D（LAYR社内ツール）、utilitarian。既存LPの意匠は維持する。
- トークン正本: `src/styles/style.css` の全4箇所の `:root` と `src/data/theme.json` を確認。既存トークンを優先し、独自の色・書体・角丸・影は増やさない。
- 色: 紙 `--paper`、地 `--bg`、文字 `--text`、補助 `--muted`、罫 `--line`、操作の強調 `--green-ink` / `--green-cta`。グラデーションなし。
- 書体: 見出し・本文・英数字とも `--font-jp`。400 / 500 / 700。数字はtabular-nums。
- 型スケール: label 12px、body/sm 14px、h3/lead 16px、h2 20px、h1 24px、集計32px。既存のサイズ集合から選択。
- 余白: tight 6px、group 22px、block 32px、画面の上下32/22px。機能画面にはLP用の大きなセクション余白を持ち込まない。
- レイアウト: 左に短い業務メニュー、右に集計・絞り込み・一覧。地域を選ぶと詳細編集ダイアログ。狭い画面ではメニューを折り返し、表内だけを横スクロールする。
- Signature: 「地域 → 狙うKW → 実績 → 次にやること」を同じ地域レコードでつなぐ台帳。未測定は数値ゼロと区別する。
- 余白の谷: ページ見出しと集計、その下の作業一覧を罫線と余白で分離。
- 変更しないもの: 既存LPの画像・価格・本文、既存CMS、会社情報、法務、記事、既存Workerの配信構成。
- 自己審査: ダミーの順位や折れ線グラフを置かない。1,965地域の正本からキーワード候補を生成し、取り込んだ検索実績と明確に区別する。

## 保存と実績

編集内容はこのURLを開いたブラウザのIndexedDBに保存する。外部サーバー・GitHubへ編集データを送らない。複数タブからの古い状態での上書きを検知する。端末やURLが変わる場合はJSONバックアップを復元する。自動クラウド同期・Google認証・Search Console APIによる自動取得は含めない。

管理対象は1,965地域と標準9,825件のキーワード候補。「どの地域で、どのキーワードを狙い、次に何を改善するか」を記録する台帳として使う。状況やキーワードの保存は運用記録の変更であり、LP本文・公開状態・検索順位を変更する操作ではない。

プレビューでは、PRに掲載した固定のブランチ別URLをブックマークする。コミットごとのプレビューURLに移動すると保存先が変わる。本番へ移行する際も、移行元でJSONバックアップを出力し、移行先で復元する。

Search Consoleのページ別・クエリ別CSVを取り込む。期間と検索条件を利用者が指定し、保存前に取り込み件数と対象外行を確認する。同じ期間・条件・集計軸は置換し、二重計上しない。異なる期間や集計軸の数値を合算しない。クエリ別実績は、ページ絞り込みが未指定ならサイト全体の実績として表示する。表示回数があってもインデックス状態を自動確定しない。

出典: [Google 検索パフォーマンスレポート](https://support.google.com/webmasters/answer/7576553?hl=ja)。平均掲載順位は検索時点・地域・端末等を含む集計値であり、固定の順位ではない。CSVの行数制限や匿名化等によって、CSVに現れないデータがある。

管理画面はnoindex、サイトマップ対象外。管理UIはアクセス制限ではない。配信されるデータは公開LPの地域・URL・キーワード候補だけで、業務メモと検索実績は利用者のブラウザ内に留まる。

## 日常の操作

1. 「地域・ページ」で地域を検索し、地域名を押す。次の作業・担当・期限を記入して保存する。
2. 「キーワード」で対策対象を確認する。各地域の編集画面で候補を保留にし、実際に狙う検索語を追加する。標準候補は実測した検索ボリュームを意味しない。
3. 「実績・入出力」でSearch ConsoleのCSVを指定し、期間・条件を合わせて内容確認→保存する。ページのフィルタをかけたクエリCSVでは、その対象ページも指定する。
4. 一覧の「表示する検索実績」で期間を切り替える。未取り込みやCSVにない数値は「—」で表示する。「改善タスク」で期限や対応状況を確認する。
5. 作業後はJSONバックアップを保存する。端末やプレビュー/本番URLを変える際は同じバックアップを復元する。CSV出力は他の表計算ソフトで確認するためのもので、復元にはJSONを使う。

保存上限は20MB、60実績、100,000実績行。上限到達時はバックアップを保存し、不要な検索実績を削除する。CSVの比較エクスポート、ページ×クエリの複合集計、UTF-8以外は受け付けず、理由を表示する。Google Search Consoleでのデータ表示・書き出しが必要で、このツールからGoogleへのログイン情報を入力する必要はない。

## 2026-09-18 更新：市単位の公開とGoogle計測

この節が上記初版の対象件数・Google接続の記述に優先する。

- 対象は792市＋47都道府県＝839地域、標準候補4,195件。町・村・区単独の1,126地域は公開対象外。旧メモ・キーワード・実績は消さず「対象外（旧データ）」で参照できる。
- 初回は名張市・鳥羽市・橋本市の3ページを公開対象とする。残る836地域は下書き。公開済みと作業ステータス・手動インデックス確認は別々に管理する。
- `/src/data/ltori-publication.json` の公開台帳に記載し、独自の募集条件整理・配信例・準備チェックリスト・公的出典・確認日が揃ったページだけ生成する。1日3件の台帳上限を検証する。未来日には生成せず、反映には当日のビルドが必要。自動cronや未確認記事の連続公開は設定しない。3件/日はSEO上の安全基準を意味せず、内容確認の運用上限。
- ビルド前に生成物を削除して、公開対象外の古いHTMLが残らないようにする。サイトマップ・一覧は公開中のLPに限定。地域LPから全国・類似地域へのリンクは復活させない。

### アクセス・問い合わせの使い方

1. 左メニュー「アクセス・問い合わせ」を開く。
2. 「Googleの接続設定」でOAuthクライアントIDとGA4プロパティIDを指定。GA4とSearch Consoleの閲覧権限を持つGoogleアカウントで接続する。
3. 期間を選び「Googleから一括取得」を押す。GA4のPV・総ユーザー数・LPを入口にしたセッション・専用問い合わせイベントと、GSCのウェブ検索クリック・表示回数・平均順位を取得してブラウザに保存する。
4. 「保存したアクセス実績」で期間を切り替える。GSC CSVを使う場合は同じ期間のページ別実績だけが選択可能。検索条件は画面に表示する。別期間の数値は足さない。
5. 一覧をCSV出力するか、既存のJSONバックアップに作業メモと一緒に保存する。Googleトークンは出力しない。

Google CloudでAnalytics Data APIとSearch Console APIを有効化し、WebアプリのOAuth設定に生成元 `https://layr.co.jp` を登録する。テスト中のOAuthアプリでは利用アカウントをテストユーザーに追加する。クライアントシークレットは使用しない。GA4の測定ID `G-J7EENJ6QV2` と数字のプロパティIDを混同しない。実データ接続は所有者のGoogle認証・OAuth初期設定が必要で、実装段階では認証済みと扱わない。

接続できない間はGA4の探索からCSV出力し、管理画面で取り込める。行は「ページパスとスクリーンクラス」、値は「表示回数」「総ユーザー数」。日付・クエリ・端末の内訳を外す。同じ地域が複数行の場合はユーザー数の重複合計を避けるためエラーとする。任意のSessions列はLPを入口にしたセッション、Inquiries列は専用イベントの完了数を指定。一般イベント数や全キーイベント数を問い合わせとみなさない。

### 計測の定義と限界

- GA4は本番ホストだけで読み込む。プレビューと管理ツールの閲覧は計測に混ぜない。
- 地域LPから相談フォームへ `service=ltori&source=area/...` を渡し、フォームサービスのJSONが成功を示した時だけ `ltori_inquiry_complete` を1回送る。既存の `generate_lead` は互換性のため維持し、今回の集計では専用イベントのみ使う。
- Google Data APIでは専用イベントと問い合わせページURLのsourceを対応づける。`page_source` のカスタムディメンション登録は不要。問い合わせ本文・メールアドレス・氏名はGA4に送らない。取得URLの生データもブラウザの集計保存には残さず、台帳IDと数値へ変換する。
- フォーム完了回数であり、有効商談数・契約数・ユニーク問い合わせ人数ではない。LINE上での会話、メールアプリからの送信、sourceのない別導線は含まない。専用イベント設置前の成果は遡及集計できない。
- GA4の総ユーザー数をページ間で足さない。流入セッションは検索以外も含み、GSCクリックと一致しない。GSCは太平洋時間、GA4はプロパティの時間帯を表示する。
- 返らない行は未取得扱い「—」。0への補完はしない。反映待ち、計測拒否、広告ブロック、しきい値、APIの集計上限で現実の全件を捕捉できない。部分失敗は他の結果を保存したうえで理由を表示する。
- Google権限は analytics.readonly と webmasters.readonly。トークンはタブのメモリのみ。再読込・期限切れで再接続。プロパティIDなどの接続設定だけlocalStorageに保存し、取得実績は既存IndexedDB・JSONバックアップへ統合する。自動クラウド同期・バックグラウンド取得は行わない。

Google公式資料：[Data API runReport](https://developers.google.com/analytics/devguides/reporting/data/v1/rest/v1beta/properties/runReport)、[指標定義](https://developers.google.com/analytics/devguides/reporting/data/v1/api-schema)、[Search Analytics query](https://developers.google.com/webmaster-tools/v1/searchanalytics/query)、[OAuth token model](https://developers.google.com/identity/oauth2/web/guides/use-token-model)。
