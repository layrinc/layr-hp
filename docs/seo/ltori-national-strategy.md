# エルトリ 全国インバウンド集客計画

更新: 2026-09-17。正本: 採用特化LINE「エルトリ」の現行サービスと、この会話の最新指示。

## 目的と成功の定義

6〜12か月をかけて、採用に課題を持つ企業から相談が続く検索集客チャネルを育てる。SEOを短期の営業施策で代替せず、他の営業経路と並行して蓄積する。以前の「100時間のR&D」「180日で成果がなければ一律統合」は、この案件の終了条件にしない。

全国の地域を管理対象とし、公開ページは地域ごとの採用判断に役立つ内容を確認してから増やす。全国対応・ページ公開・インデックス・順位・相談・受注は別の状態として扱う。全国の検索語での上位表示や問い合わせの獲得を保証する計画ではない。

## 検索の入口は3軸

| 軸 | 検索意図の仮説 | ページの役割 |
| --- | --- | --- |
| 地域 | 和歌山 採用LINE、名張市 採用 LINE 構築 | 地域の採用情報、勤務地・見学の具体的な案内、オンライン支援の説明 |
| 業種 | 製造業 LINE 採用、建設業 採用 LINE、運送会社 採用 LINE | 職種・条件・応募前の不安に応じた配信と導線 |
| 課題 | 採用LINE 費用、面接辞退 対策 LINE、内定者フォロー LINE | 課題の整理、できること/適用条件、具体的な設計例 |

上記はキーワード候補。検索数を取得した事実はない。「採用 LINE」は求職者・自治体の公式LINE・企業の採用窓口を探す意図とも混ざるため、採用担当者向けであることをタイトルと本文で明示する。集客一般の `/service/line/` と採用の `/service/ltori/` は意図を分ける。地域×業種×課題の全組合せは生成しない。

## URLと生成の設計

- 全国入口: `/service/ltori/area/`
- 府県: `/service/ltori/area/wakayama/`
- 市: `/service/ltori/area/wakayama/hashimoto/`
- 業種: `/service/ltori/industry/manufacturing/`
- 課題: `/service/ltori/guide/<topic>/` を次フェーズで必要な内容から追加。

同一ドメインのサブディレクトリで運用・内部リンク・サービス情報を集約する。サブディレクトリであること自体が順位上昇を保証するわけではない。行政区域はJISコードで識別し、同名市町村・郡・政令市の区を区別する。政令市と区の両方を公開するかは内容・意図の違いで判断する。

## 段階と作業量の目安

以下は制作・検証の計画であり、成果予測ではない。月10〜20ページ程度の新規調査・原稿確認に使える体制を一つの仮置きとし、実測工数と品質に合わせて調整する。全国すべての個別LPを12か月以内に作る約束はしない。

| 期間 | 実施内容 | 判断に使う情報 |
| --- | --- | --- |
| 初月 | 全国台帳、料金/CTA共通化、計測設計、初期8ページ、需要と検索意図の調査 | 公開・クロールの可否、フォーム動作、検索語の妥当性 |
| 2〜3か月 | 初期候補5府県30市を調査。10市程度ずつ内容レビュー。業種と費用・運用課題のページも整備 | インデックス状況、表示され始めた検索語、掲載順位より検索意図 |
| 4〜6か月 | 反応のある地域・業種を深掘り。相談で分かった質問をFAQ・作例へ反映。許諾済みの採用事例を追加 | 有効相談、商談化、受注、公開からの経過日数ごとの傾向 |
| 7〜12か月 | 調査と編集の体制が回る範囲で全国へ順次拡大。既存ページの更新を優先枠として確保 | 相談・受注への貢献、制作保守コスト、重複・陳腐化の有無 |

90日と180日はレビューの節目。例えば「公開後90日以上のページのインデックス率70%」「180日で有効相談3件/運用受注1社」は仮の参考目標にできるが、採用はしないまま確定KPIとして扱わない。未達時は需要・内容・技術・競合・時期を分けて診断する。地域名だけの重複ページ、意図が重なるページは個別判断で統合する。

## 調査・編集の基準

1. 自治体・労働局・e-Stat等の一次資料を確認。統計を使う場合は集計範囲・対象年度・出典を明記する。
2. 採用企業がその地域で判断する内容に結び付ける。事業所の職種、通勤、見学、U・Iターン、説明会後の連絡など。
3. 配信例・メニュー例は企業の条件に合わせた作例として表示し、実在企業の成果と混同しない。
4. 料金は `service-ltori.json` から取得。ツール利用料や追加作業の条件を明記。
5. オンラインの対応方法を記載。実在しない拠点・住所・支援実績を作らない。
6. 出典、確認日、編集主体を表示。原稿確認とブランド/事例の許諾は公開前のPRで確認する。
7. 1ページで検討できる内容にする。同じ相談先へのリンクがあるだけで判定せず、地域ごとの実質的な有用性を審査する。
8. `ready` のみHTMLを生成。未調査データはページ・サイトマップに出さない。出典や親ページが欠けるデータはビルドを止める。

人材不足率や応募改善率を推測で書かない。人口や産業名を加えるだけでGoogle方針に適合するとの保証もしない。AIは調査整理・下書き・整形・差分チェックに使い、根拠の確認とサービス条件の承認を公開工程に残す。

## 計測と運用

| 段階 | 情報源・記録 | 今回の状態 |
| --- | --- | --- |
| 検索に出る | Search Consoleのページ/クエリ・表示・クリック・登録状況 | 権限・現在値は未確認 |
| 読まれる | 既存GA4。地域・業種のURLごとに確認 | 既存IDを利用。実データ取得は未実施 |
| 相談が始まる | CTAクリック `select_content`、`page_source` | 実装・ローカル検証対象 |
| フォームが送信される | 既存 `generate_lead` に `page_source` を付加 | 送信成功時のみ。クリックをCVに数えない |
| 有効相談・商談・受注 | 実際の問い合わせ内容と営業記録で判定 | 手動記録の運用が必要。今回CRMは増設しない |

`source` はサイト内の既知のページIDに限定し、自由入力の会社名・氏名・メールアドレス等をGA4に送らない。フォーム通知とメール下書きにはページの表示名を引き継ぐ。LINEへ直接移動した場合の相談成立・電話・複数回訪問の帰属は今回の実装だけでは測れない。`generate_lead` はフォームの受付成功を示し、営業上の有効相談・受注とは区別する。

公開前にGA4でカスタムディメンション `page_source`、キーイベント `generate_lead` の設定状況を確認。Search Consoleで正規URLとサイトマップを確認する。公開後は少数ページをURL検査し、全件を機械的にインデックス申請しない。

月次: 検索語・内容・相談のレビュー。四半期: 地域/業種の優先順位と制作コスト。半年: 有効相談と売上貢献。継続的な自動実行・通知・有料ツール契約は設定していない。

## 今回の実装と残る工程

全国47都道府県のハブ、和歌山/橋本・三重/名張の地域原稿、製造/建設/運送物流の業種原稿、全国地域マスター、30市調査候補、公開制御と計測導線を用意。本番への公開、残り28市の個別調査、追加3府県の原稿、課題ページ、実績取材、Search Console/GA4管理設定は次工程。

`AGENTS.md` の既存フローに従い、PR→Cloudflareプレビュー→CI→河出さんの承認後にマージ。本番Git連携を未確認のまま「マージで公開済み」と扱わない。
