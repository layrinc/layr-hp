# LAYR SEOワークスペース — 統合SEO・AIO戦略

更新日：2026-09-22。対象は全国SEO、エルトリ採用ノート、LAYR公式メディアの3施策。

本書は、河出さんの「参考情報を踏まえて戦略を作り直す」という依頼に基づく運用提案。提供された動画の文字起こしは判断材料として扱い、動画内の主張を検索エンジンの仕様や実証済みの法則とは扱わない。この記事計画による順位・問い合わせの増加を保証するものではない。

## 1. 読者に提供する価値と着地点

**全国の中小企業の採用担当者が、応募から入社までのLINE導線を、具体的な手順・費用条件・運用例から判断できる情報を届ける。**

採用課題を整理し、社内で対応できる範囲と支援が必要な範囲を判断できる状態を目指す。記事から、関連する実務記事、サービス内容、相談へと進める導線を設計する。すべての記事でサービスを押し出す必要はない。

この一文は今後の編集方針であり、実績の自己評価ではない。「全国で導入多数」「採用率が改善」「AIに選ばれている」といった表現は、確認できる根拠なしに掲載しない。作成した配信フローは「作例」、実際の成果は許諾と計測条件のある「事例」として分ける。

管理画面は `seo.layr.co.jp` 内で切り替える。管理画面の `/media/` は採用ノートの管理であり、公開サイト `layr.co.jp/media/` とは区別する。公開記事のURLは今回変更しない。

公式メディアには2026-09-22時点で23本の非下書き記事がある。一般LINEの記事群を、採用に特化した記事群と同一視しない。本文は今回変更していない。

### 1つの検索意図に1つの主担当URL

- 「採用 LINE 費用」「LINE 採用 費用」のように同じ判断を求める候補は、同じ記事で扱えるか先に確認する。表記違いだけで記事を増やさない。
- 「LINE公式アカウント 運用費用」は公式メディア、「採用LINE 導入費用」は採用ノートが主担当。一般的な説明は内部リンクで補い、全文を複製しない。
- 地域名を含む相談意図は地域ページが主担当。全国共通の配信手順は採用ノートへ案内する。
- 重複が見つかった記事は「更新候補」「統合検討」として記録する。既存記事の削除・URL変更・転送は自動実行しない。

## 3. キーワードを採用する順序

| 判定順 | 確認すること | 結果 |
| --- | --- | --- |
| 1. 事業との適合 | 企業の採用担当者の意思決定に役立つか。求職者向けの検索と混ざっていないか | 対象／保留と理由を記録 |
| 2. 書ける内容 | 公的資料、確認済みの仕様、独自の作例や手順を用意できるか | 根拠の揃った企画を制作候補へ |
| 3. 検討の近さ | 費用・比較・導入・外注などの導入判断か、具体的な課題改善か | 顕在／潜在／実務に分類 |
| 4. 主担当URL | 既存記事で答えられないか。3施策のどこが担当するか | 新規／既存更新／統合検討 |
| 5. 検索需要 | 同じ対象・制作準備度の候補を、同条件の検索ボリュームが大きい順に並べる | 制作順を決める |

河出さんの「検索数の大きいものから制作する」方針を維持する。検索意図が対象外の大量検索語を、数値だけで採用しない。編集上の例外で順序を変えるときは、必要な根拠記事の不足や直近の相談内容など、理由を残す。固定の点数式を検索エンジンの評価式と称して導入しない。

月間10程度の候補も残す。検索数は検索の需要を示す推計値であり、10検索＝10PVではない。提供元で0を確認した候補は黒塗りとし、候補を自動削除しない。未取得・取得失敗・範囲値は0と分ける。0の候補を制作する場合は、実際の相談や既存記事を補う役割など、別の根拠を記録する。

「〜とは」は一律に除外しない。導入判断に必要な基礎記事が不足している場合は採用し、用語の説明だけで終わらず、採用担当者が次に決める内容へつなげる。

### 各候補に残す項目

候補ID／施策／想定読者／読者の悩み／主キーワードと関連語／検索意図／既存の主担当URL／新規または更新／独自に提供する手順・作例／根拠資料URLと確認日・対象範囲／月間検索数と取得元・地域・言語・期間／制作判断と理由／担当・期限／次のアクション／公開URL。

これらは編集運用の記録仕様。一部は既存のメモ欄・計画シートを使う。すべてが今回の管理画面で専用入力欄として実装された、という意味ではない。

## 4. 採用ノートの制作候補と月10本の配分

月10本を継続できる場合の配分例は、**顕在4本・潜在4本・実務2本**。これは編集枠の提案で、確定した制作順ではない。各枠の中では、実測した同条件の検索数が大きい候補から選ぶ。需要の偏りや制作負荷に応じて月次で見直す。

次の10テーマは検索ボリューム未確認の案であり、既存記事と同じ検索意図なら新規追加せず更新へ回す。

| 枠 | 調査する候補語 | 提供する内容・差別化の材料 | 最初の確認 |
| --- | --- | --- | --- |
| 顕在 | 採用 LINE 費用 | 初期構築、配信、運用工数を分ける費用表の作例 | 公式料金と課金条件の確認、既存記事照合 |
| 顕在 | 採用 ツール 費用 | 応募管理・日程調整・連絡の機能別に、必要な費用を比べる | 現行ツールの公式料金・機能の確認 |
| 顕在 | 採用 おすすめ 媒体 | 募集職種・採用人数・応募後対応に合わせた選択手順 | 読者と比較条件を確定。順位を先に決めない |
| 顕在 | 採用 LINE 外注 | 委託範囲、社内に残す役割、見積依頼項目 | 公開済みサービス内容と一般的な判断軸を分ける |
| 潜在 | 面接 日程調整 効率化 | 候補日受付から前日連絡までのフローと例外対応 | 既存の日程調整記事と検索意図を照合 |
| 潜在 | 面接 辞退 対策 | 辞退理由の整理、連絡タイミング、改善の確認方法 | 効果を断定せず仮説と測定方法を示す |
| 潜在 | 採用 業務 効率化 | 作業棚卸しと、LINE・メール・管理表の使い分け | 人事の相談メモや工数記録を確認 |
| 潜在 | 応募者 連絡 つかない | 応募直後の連絡設計、再連絡、対応終了条件の作例 | 送信回数などの条件を作例として明記 |
| 実務 | 内定者 フォロー LINE 例文 | 内定後から入社前までの配信例と運用担当 | 実績と誤解されない作例、既存記事との重複確認 |
| 実務 | 採用 LINE リッチメニュー | 応募・職場見学・FAQ・日程確認への導線例 | 使う機能の公式仕様と画面例の確認 |

記事は結論、適用条件、具体的な手順、選択基準、作例、根拠・確認日、次に読む記事を持つ。サービス比較では対象範囲と比較基準を示し、未確認の料金・架空の実績・意図的な自社1位の表を作らない。

## 5. 全国SEOの公開条件

現行カタログには1,965の地域レコードがあるが、公開対象の判定は**47都道府県と792市、計839件**。これは公開済み件数ではない。町・村・区の旧データは保持しており、現行の新規公開対象ではない。町村向けの拡張は、地域データ・公開機能・編集基準を確認してから別途進める。

新規の市ページは、次の材料を揃えてから公開判定する。

1. 自治体・労働局・公的統計などの一次資料について、対象地域、対象期間、確認日を記録する。県や全国の数値を市の数値として扱わない。
2. 地域の職種、勤務地、移動、勤務形態などの事実から、採用案内で解決すべき課題を具体化する。地域の全企業に同じ事情があると断定しない。
3. 課題に対応した応募・見学・面接・入社前のLINE案内を作例として記載する。
4. 根拠のない地域実績や現地拠点を付け加えず、サービス提供範囲を正しく示す。
5. 既存ページとの差が地名の置換だけなら公開待ちに入れず、追加調査または既存ページの改善へ戻す。

Googleは、利用者への価値が乏しい大量生成や、似た地域ページから同じ場所へ誘導する仕組みをスパムの例として説明している。ページ数や少量ずつの公開だけで品質を判断しない。[Google検索のスパムポリシー](https://developers.google.com/search/docs/essentials/spam-policies)

## 6. SEOとAIOに共通する制作基準

Google検索のAI機能でも基本的なSEOが有効であり、専用のAI用ファイルや特別な構造化データは必須ではない。まず、検索で発見・閲覧できるページと、読者が判断できる内容を整える。[Google：AI機能とウェブサイト](https://developers.google.com/search/docs/appearance/ai-features)

一般論の言い換えだけでなく、独自に確認した材料、実務手順、比較条件、写真や図解が必要な箇所を用意する。生成AIは下調べ・整理・草案に使い、根拠と利用者にとっての価値を編集者が確認する。[Google：生成AI検索向けの最適化](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide)

実行することは、明確な見出し、本文に表示した根拠と確認日、内容に合った内部リンク、実体のある運営・著者情報、表示内容と一致する構造化データ、古い仕様の更新。第三者による紹介や評価は実際に得たものを扱い、架空の推薦や購入した評価を作らない。

参考動画からは、事業との適合、独自に提供できる内容、具体的な検討に近い記事を重視する考え方を採用する。一方、「AIは必ずウェブ検索する」「上位30ページが固定の参照範囲」「独自性×第三者評価×検索順位という共通の計算式」は、確認済みの仕様として採用しない。AIサービスや質問によって挙動は異なる。

## 7. 12か月の進め方

| 時期 | 制作・改善の重点 | 見直しに使うもの |
| --- | --- | --- |
| 初月 | 3施策の記事と主担当URLを整理。費用・導入・日程調整の制作候補を調査し、初月10本以内の制作枠を決める。公式23記事は改善対象を選ぶ | 計測対象URL、取得期間、検索需要の取得条件、公開前の根拠 |
| 2〜3か月 | 顕在・潜在・実務の不足を補い、需要が見えた記事を更新。全国SEOは根拠を揃えた市から進める | 検索表示・クリック、CTAと完了の差、担当者の相談内容 |
| 4〜6か月 | 問い合わせにつながるテーマを深め、反応が弱い記事の意図・タイトル・導線を見直す | 同期間の推移、検索語、実際の有効相談・商談記録 |
| 7〜12か月 | 許諾済みの実例を増やし、地域・職種・導入段階ごとに不足情報を補う。重複候補と制作負荷を再点検 | テーマ別の成果、制作・更新コスト、情報の古さ |

年間120本は「月10本を12か月続けた場合」の容量目安であり、品質条件を満たさない月に本数を埋める義務ではない。短期の順位変動だけで一律に中止せず、同時に、根拠や問い合わせ導線の不備を長期間放置しない。

月ごとのテーマ例：1か月目は費用・導入判断、2か月目は応募直後、3か月目は日程調整、4か月目は面接前後、5か月目は内定後、6か月目は工数・社内体制、7か月目は職種別、8か月目は地域別の課題、9か月目はツール連携、10か月目は文面・画面の作例、11か月目は計測と改善、12か月目は料金・仕様の再確認と年間見直し。各月で顕在・潜在・実務を混ぜ、需要調査によって順序を入れ替える。

## 8. 計測と改善の運用

| 周期 | 行うこと | 記録する結果 |
| --- | --- | --- |
| 日次の既存取得 | GA4・Search Consoleの取得状態と保存 | 取得元、期間、成功日時、エラー。画面上の最終成功で確認 |
| 週次 | 施策ごとの検索表示・クリック・PV・CTA・問い合わせを確認し、改善対象を選ぶ | 対象URL、根拠、変更案、担当、確認予定日 |
| 月次 | 市場の検索需要を更新し、候補の採否と制作順、既存記事の更新を見直す | 取得条件を揃えた検索数と採否理由 |
| 月次のAIO観測 | 決めた質問を同じ条件で確認し、引用URLと説明内容を記録する | 実施日、AIサービス、表示されたモデル・検索利用条件、質問全文、引用URL、言及内容 |

SEOの計測値とAIOの観測は別物。Search Consoleの検索表示回数は市場の検索数ではない。GoogleのAI機能からの掲載・クリックはSearch Consoleのウェブ検索の実績に含まれるため、現在の一覧を「AIに引用された回数」と読み替えない。[Googleの計測説明](https://developers.google.com/search/docs/appearance/ai-features)

AIOの観測は、現時点では手動で行う運用案。自動監視・引用率の集計機能は未実装。同じ質問でも結果が変わるため、限定した質問セットでの観測と明記し、市場全体での評価とみなさない。

固定質問の例：

- 中小企業の応募者対応を減らすには、どこから見直すとよいですか。
- 面接の日程調整を効率化する方法を、費用と運用負担で比較してください。
- 採用にLINEを導入する場合、社内で準備することは何ですか。
- 採用LINEの構築を外注するとき、見積もりで比較する項目は何ですか。
- ［選定した市］で採用する企業が、応募後の辞退を減らすために確認することは何ですか。

市の質問は対象市を固定して比較する。自社名を含む質問と含まない質問を分け、指名質問の回答を一般的な推奨の実績と扱わない。

## 9. 現在の機能とこれから接続するもの

- GA4・Search Consoleのサーバー取得は既存機能。今回の統合で3施策のURL範囲ごとに参照する。取得できない数値は未取得として扱う。
- 検索ボリュームは取得済みCSV等で管理。Google広告APIなどの市場需要API、競合の定期取得は未接続で、完全なリサーチ自動化はまだ動いていない。
- 採用ノートの企画・編集メモにはブラウザ内保存の項目がある。共通ナビへの統合だけで、すべてが端末間共有やシート書き戻しになったわけではない。
- 編集者が対象・根拠・原稿を確認して公開を判断する。市場調査から公開までを無人で確定する運用にはしていない。
- 共通公開機能の1日最大10本という上限は運用上の制限。採用ノートの月10本という制作目安とは別で、今回スケジュールや上限は変更しない。公式メディアの記事本文・公開手順も変更しない。

### 次の実務

1. 初月の候補を既存記事に照合し、3施策の主担当URLを決める。
2. 検索数と根拠資料を揃え、同条件では検索数の大きい順で制作候補を選ぶ。
3. 手順・作例を入れた原稿を確認し、公開後のURLを管理画面に紐づける。
4. 週次で成果と改善を確認する。月次で需要とAIOの観測を照合し、次月の制作枠を調整する。
