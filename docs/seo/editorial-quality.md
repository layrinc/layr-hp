# エルトリ：確認済みコンテンツの公開運用

## 運用の前提

- 対象は企業の採用担当者。求職者向けの求人ページと区別する。
- 地域LPは既存のエルトリLPをテンプレートにし、自治体マスターにある「市」のみ扱う。町・村・行政区は公開しない。
- 1日10件は日本時間での公開上限。未確認の原稿を10件に水増ししない。ページ数・公開速度だけで検索掲載や安全性を保証できない。
- LPには全国一覧・ほかの対応地域への回遊リンクを表示しない。メディアの記事や地域索引から、内容に関係する公開ページへリンクする。
- 同じ市を複数ページに増殖させない。市LPのパスは `/service/ltori/area/{県slug}/{市slug}/`、記事は `/service/ltori/media/{slug}/` で固定する。

## 原稿と承認

原稿の状態は `draft` → `approved` → `scheduled` → `published`。一時停止は `paused`。
承認者・承認日時・公開日時はAPIが記録する。ブラウザから送った承認情報は信用しない。
公開済みの原稿を編集したときは、現在の公開版を保ちながら別の下書きを確認し、改めて承認する。

確認項目：

1. 検索意図が企業の採用課題に合っている。
2. タイトル・説明・主見出し・導入文が本文と一致する。地域LPのタイトルと主見出しには市名を入れる。
3. 課題、実施方法、手順など、読者が行動できる節を3つ以上用意する。節数そのものはSEO評価基準ではない。
4. そのまま検討に使える配信文や運用手順の作例を示す。作例を実績として扱わない。
5. 地域・業界の事実には公開URL、資料名、確認日、資料の対象範囲を記録する。県の統計を市の統計として引用しない。
6. 出典を開き、本文の主張を支えているか人が確かめる。URLの形式が正しくても事実確認にはならない。
7. 実在しない拠点・顧客・成果、順位保証、根拠のない改善率を書かない。現地訪問や撮影を約束せず、既存の提供条件に従う。
8. 他の記事と同じ本文、地名を入れ替えただけの本文になっていないか比較する。

自動チェックは入力漏れ・日付・URL・市区分・同一節の重複を検出する。独自性、出典との一致、検索意図の最終判断は担当者が行う。「SEO安全点」「Google合格率」のような点数は付けない。

## 入力形式

```json
{
  "type": "city",
  "slug": "mie/nabari",
  "title": "名張市の採用LINE構築・運用支援｜エルトリ",
  "description": "検索結果に表示する説明",
  "heading": "名張市の採用LINE構築・運用支援",
  "lead": "この市で採用する企業に役立つ導入文",
  "intent": "employer",
  "sections": [
    {"heading":"課題", "paragraphs":["根拠と意味"], "steps":[]},
    {"heading":"実施方法", "paragraphs":["具体的な設計"], "steps":[]},
    {"heading":"進め方", "paragraphs":[], "steps":["担当者が行うこと"]}
  ],
  "example": {"label":"作例", "title":"配信文の作例", "body":"配信本文"},
  "sources": [{"title":"資料名", "url":"https://example.com/", "checkedAt":"2026-09-21", "geographicScope":"名張市"}],
  "relatedCitySlugs": []
}
```

本文はプレーンテキスト。HTMLやMarkdownは実行・解釈しない。表示時にすべてエスケープする。
記事の `relatedCitySlugs` は本文に関係する市を最大3件まで選べる。実際に公開されている市だけをリンクにする。

## 公開と技術面

- 公開HTMLには個別のtitle、description、canonical、構造化データを出力する。
- 既存のサービスLP／採用コラムのデザイン・料金を再利用し、原稿から料金や会社情報を上書きしない。
- 内部の `/service/ltori/article-template/` は一般公開・サイトマップから除外する。
- 下書き・予約前・停止中の新規URLは検索対象にしない。認証済みのプレビューは `noindex, nofollow`・`private, no-store`。
- サイトマップ・記事一覧には実際の公開版だけを載せる。元の下書きではなく公開スナップショットを参照する。
- 別端末からの上書き競合はバージョン番号で検出し、最新を確認してから保存する。

## 改善の判断

検索表示・クリック・問い合わせ完了・有効な相談・商談・受注を分ける。LINEクリックは問い合わせ完了ではない。
少数アクセスでの率の上下だけを根拠に削除や統合を決めず、インデックス、需要、検索意図、本文、相談導線を順に確認する。
