# LAYR HP 開発ガイド（自分でコーディングする人向け）

河出さんが自分でコードを触るときの早見表。AI（レイ）と共同開発する前提の構成。

## ローカルで動かす

```bash
cd 株式会社LAYR/layr-hp
npm run dev        # http://localhost:4321 で起動。保存すると即反映（ホットリロード）
```

公開は保存不要の自動方式：**mainにpushすれば1〜2分で本番反映**（GitHub Actions → Vercel）。

## どこを触ると何が変わるか

| 変えたいもの | 触る場所 |
|---|---|
| 文言・数値・写真 | 管理画面（/admin）または `src/data/*.json` ※どちらでも同じ |
| 色・角丸・フォント | まず管理画面「⑨デザイン設定」。それ以上の細かさは `src/styles/style.css` の`:root`変数 |
| 見た目・レイアウト全般 | `src/styles/style.css`（サイト唯一のCSS。セクションごとにコメント区切り） |
| ページの構造・セクション追加 | `src/pages/index.astro`（トップ）、`src/pages/blog/`（コラム） |
| ヘッダー・フッター・SEOタグ | `src/layouts/Base.astro`（全ページ共通の骨格） |
| 記事の見た目 | `style.css` の「記事ページ」セクション（`.article` 系） |
| 管理画面のフォーム項目 | `public/admin/config.yml` |
| 新しいページを作る | `src/pages/xxx.astro` を作ると `/xxx` が生える（`Base`で包むとヘッダー等が付く） |

## 設計のルール（崩さないための約束）

1. **色は直書きしない** — 必ず `var(--green)` などのCSS変数を使う（⑨デザイン設定が効かなくなるため）
2. **文言はコードに書かない** — 編集したくなる文字は `src/data/*.json` に置き、`config.yml` にフォームを足す（レイに「この項目もCMS化して」と言えば対応）
3. **SEOはBase.astroに集約** — title/description/canonical/OGP/JSON-LDはページから`Base`に渡す。個別ページで`<head>`を書かない

## SEOとして実装済みのもの

- 静的生成（Astro）＝表示速度がほぼ満点 → Core Web Vitals対策
- sitemap.xml 自動生成・robots.txt・canonical・OGP
- 構造化データ: Organization（会社）/ BlogPosting＋パンくず（記事）/ FAQPage（よくある質問）
- 記事ごとのtitle・description・OGP画像を管理画面から設定可能

## 上位のカスタマイズはレイへ

「セクションを丸ごと追加」「アニメーション変更」「新レイアウト」などの大工事は、Claude Codeでレイに指示するのが速い。河出さんの手書きコードとの共存は問題ない（このガイドのルールに沿っていれば衝突しない）。
